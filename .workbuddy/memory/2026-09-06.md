## 坑：崩溃后 NTFS 目录索引损坏
- 崩溃后 `.git/refs/remotes/origin/` 等目录新建文件"隐形"（写入成功但 readdir 看不到，跨进程随机消失）。
- 解法：`git pack-refs --all --prune` 把全部引用收进单文件 packed-refs，绕开坏目录索引。
- 建议：待办 chkdsk C: /f（需重启）修复文件系统，否则其他目录也可能踩同样的坑。

## A 方案落地：任务级 token 消耗（网关 v0.6 / 镜像 0.6.0，提交 5251bc72e1）
- 用户外挂插件 usage-probe.js（CJS，--patch file:/// 注入，零 dsh 内核改动）：监听 assistant/message 事件 data.usage（provider 精确值）任务级累加原子写盘 → 网关 close 时读取 → /task/:id 与 SSE done 返回 usage{calls,inputTokens,outputTokens,totalTokens,cacheRead,cacheWrite,reasoning}。
- 关键发现：--patch 覆盖列表普通行=按 id 覆盖已有插件（匹配不到仅 warn 静默跳过），新插件必须用 `- insert:` 块（app-boot applyEntryPatches 语义）——第一次没用 insert 导致插件静默不生效。
- cordis EntryTree.import 支持 file:/// 本地插件；unwrapExports 兼容 CJS module.exports。
- 端到端实测（真实任务）：usage 自洽 totalTokens=8012=input168+cacheRead7808+output36，缓存命中占比极高 → 积分计费必须 input/cache/output 三段分开算。
- 0.6.0 已推 ACR（digest 349b97af）；demo finishChat 增加 token 显示行；API.md 补 usage 字段与版本行。

## 插件防卸载分析 + env 加固（镜像 0.6.1，digest 见 ACR）
- 结论：usage-probe 不可被用户对话卸载——patch 由网关每任务硬编码重新注入；/opt/gw root 0644 node 用户删不掉；模型无任何工具能操作 cordis entry 树；插件"内存累加+每事件全量重写"设计使 /tmp usage 文件篡改最终被覆盖（最后一次 flush 后 agent 无执行机会）。
- 注意：fs-sandbox workspace-write 放行写 workspace + /tmp（README 明确）；danger-full-access 可绕过但产品模式锁死 permissionMode。
- 加固：gateway spawn dsh 子进程剥离 GW_ADMIN_TOKEN/GW_TOKEN（agent bash env 之前可见平台令牌，prompt-injection 可窃取调 /settings）。实测 agent 执行 env|grep GW_ 只见 GW_PORT。DEEPSEEK_API_KEY 保留（dsh 必需）。
- 版本规则应用示范：网关代码未升版 → 镜像走第三位 0.6.1。
